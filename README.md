# VIN Telegram Bot — облачный запуск 24/7 без Docker

## Важно: Telegram не является хостингом

Telegram и `@BotFather` выдают токен и передают сообщения, но **не запускают Python-код бота**. Telegram Mini Apps тоже требуют внешний сервер. Чтобы бот совсем не зависел от домашнего ПК, его нужно один раз разместить на постоянно работающем облачном VPS.

Для этого проекта рекомендуется небольшой **Ubuntu 24.04 VPS в ЕС**:

- 2 ГБ RAM или больше;
- 15–20 ГБ SSD;
- Ubuntu 24.04 x64;
- постоянный публичный IP;
- исходящие HTTPS-соединения к Telegram.

Домен, веб-сайт, открытый порт для бота, Docker, VPN и прокси на сервере не нужны. Бот использует long polling, запускается через `systemd`, автоматически перезапускается и продолжает работать при выключенном домашнем ПК.

## Что останется на сервере

- программа: `/opt/vin-bot`;
- секретный токен: `/opt/vin-bot/.env`;
- база карточек: `/opt/vin-bot/data/bot.db`;
- локальный журнал: `/opt/vin-bot/logs/bot.log`;
- резервные копии базы: `/opt/vin-bot/data/backups` (дважды в сутки, хранятся 30 дней);
- служба: `vin-telegram-bot.service`.

## 1. Получите VPS

В панели любого VPS-провайдера создайте сервер с Ubuntu 24.04 в Германии, Нидерландах или другой стране ЕС. Сохраните IP-адрес и пароль `root` либо SSH-ключ.

Платформа с бесплатным «засыпающим» тарифом не подходит: Tesseract OCR требует системный пакет, а SQLite — постоянный диск. Обычный VPS надёжнее и проще восстановить.

## 2. Загрузите ZIP с Windows

Распакуйте облачный архив на своём ПК. Откройте PowerShell в папке, где находится каталог проекта, и выполните:

```powershell
scp -r .\VIN-Bot-Cloud root@IP_СЕРВЕРА:/root/
ssh root@IP_СЕРВЕРА
```

Вместо `IP_СЕРВЕРА` укажите адрес VPS. Можно использовать WinSCP, если удобнее графическое окно.

## 3. Установите одной командой

На сервере:

```bash
cd /root/VIN-Bot-Cloud
bash deploy/install-ubuntu.sh
```

Установщик автоматически:

1. установит Python, Tesseract OCR и SQLite;
2. создаст отдельного системного пользователя `vinbot`;
3. скопирует программу в `/opt/vin-bot`;
4. создаст виртуальное окружение и установит библиотеки;
5. скрыто запросит `BOT_TOKEN`;
6. запросит Telegram ID сотрудников и администраторов;
7. создаст и включит службу `systemd`;
8. включит ежедневное резервное копирование базы;
9. запустит бота и проверит его состояние.

Вводимый токен не отображается. Заполненный `.env` получает ограниченные права и не попадает в архив или репозиторий.

## 4. Проверка и управление

```bash
systemctl status vin-telegram-bot
journalctl -u vin-telegram-bot -f
systemctl restart vin-telegram-bot
systemctl stop vin-telegram-bot
systemctl start vin-telegram-bot
```

После строки `Подключение к Telegram выполнено` или `VIN-бот запущен` откройте Telegram и отправьте боту `/start`.

## Перенос существующих карточек с Windows

Чтобы сохранить старые карточки и фотографии, используйте **тот же токен того же Telegram-бота**.

1. На Windows выполните `DISABLE-AUTOSTART.cmd`, чтобы старый экземпляр больше не опрашивал Telegram.
2. Скопируйте старый файл `data\bot.db` на сервер, например через PowerShell:

```powershell
scp .\data\bot.db root@IP_СЕРВЕРА:/root/bot.db
```

3. На сервере остановите службу, замените базу и снова запустите:

```bash
systemctl stop vin-telegram-bot
cp /root/bot.db /opt/vin-bot/data/bot.db
chown vinbot:vinbot /opt/vin-bot/data/bot.db
chmod 600 /opt/vin-bot/data/bot.db
systemctl start vin-telegram-bot
journalctl -u vin-telegram-bot -n 50 --no-pager
```

Нельзя одновременно запускать один токен на ПК и VPS: два long-polling процесса будут конфликтовать. Старые Telegram `file_id` фотографий продолжают работать при использовании того же бота и токена.

## Обновление без потери данных

Распакуйте новую версию во временную папку на VPS и снова запустите:

```bash
cd /root/VIN-Bot-Cloud
bash deploy/install-ubuntu.sh
```

Установщик заменяет только программу и зависимости. Файлы `.env`, `data/bot.db`, `logs` и резервные копии сохраняются. Перед крупным обновлением можно сделать копию вручную:

```bash
/usr/local/sbin/vin-bot-backup
ls -lh /opt/vin-bot/data/backups
```

## Резервные копии и архив в Telegram-канале

За данные отвечают четыре независимых слоя:

1. **Копии на сервере.** Бот сам создаёт копию при запуске, перед каждой заменой базы и раз в сутки; служба `systemd` делает ещё две копии в сутки. Хранится 30 дней, дальше старые копии удаляются (еженедельные и ежемесячные остаются дольше).
2. **Раздел «💾 Резервные копии» в админ-панели.** Администратор и главный администратор могут выгрузить базу файлом в Telegram, загрузить её обратно, откатиться на любой день, вернуть карточку из корзины и посмотреть журнал действий. Перед каждой заменой бот автоматически сохраняет нынешнюю базу.
3. **Корзина.** Удалённая карточка не исчезает: она помечается удалённой и 30 дней лежит в корзине. Окончательно уничтожить её может только главный администратор и только через 30 дней.
4. **Архив в Telegram-канале** (по желанию). Если в `.env` указать `ARCHIVE_CHANNEL_ID`, бот сразу после создания карточки дублирует в канал все фотографии и VIN, а раз в сутки присылает туда же файл базы. Так фотографии и данные защищены даже от полной потери сервера.

Как включить архив:

1. Создайте канал (лучше приватный) и добавьте бота администратором с правом публикации сообщений.
2. Укажите в `.env`: `ARCHIVE_CHANNEL_ID=@имя_канала` либо `-1001234567890`.
3. Перезапустите бота: `systemctl restart vin-telegram-bot`.

Восстановление базы из копии на сервере:

```bash
sudo bash /opt/vin-bot/deploy/restore.sh              # список копий
sudo bash /opt/vin-bot/deploy/restore.sh latest       # последняя копия
sudo bash /opt/vin-bot/deploy/restore.sh bot-20261106T233000Z.db.gz
```

Копии на сервере защищают от ошибки и от злоумышленника в боте, но не от потери самого сервера. Поэтому раз в сутки выгружайте файл базы во внешнее хранилище, либо включите архив в Telegram-канале.

## Файл токена

Рабочий файл `/opt/vin-bot/.env` выглядит так:

```dotenv
BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
ALLOWED_USER_IDS=123456789,987654321
ADMIN_USER_IDS=123456789
TIMEZONE=Europe/Berlin
DATABASE_URL=sqlite+aiosqlite:///data/bot.db
LOG_LEVEL=INFO
TELEGRAM_PROXY=
TELEGRAM_PREFER=direct
FORCE_IPV4=true
TESSERACT_CMD=/usr/bin/tesseract
```

`TELEGRAM_PROXY` не обязателен: пустое значение означает прямое подключение к Telegram — ни VPN, ни другая программа не требуется. Если указать локальный SOCKS5-прокси, он используется только как запасной вариант. `TELEGRAM_PREFER=direct` пробует сначала прямое подключение; `proxy` — сначала прокси.

Не присылайте токен в переписке и не добавляйте `.env` в GitHub. Если токен когда-либо публиковался, выполните `/revoke` в `@BotFather` и установите новый.

## Возможности бота

- интерфейс на русском и немецком;
- карточка: фото автомобиля → полная накладная → отдельный VIN-фрагмент;
- просмотр полной накладной прямо из карточки;
- OCR немецких полей `Fahrgestell-Nummer`;
- распознание VIN по фотографии на своём компьютере, без интернета и без оплаты;
- необязательный «второй читатель» (Google Gemini) для трудных снимков: ключ добавляется в `.env` рядом с токеном бота, без ключа бот работает как раньше;
- обязательная проверка всех 17 и последних 6 символов;
- поиск всех совпадений по последним 4 или 6 символам;
- поиск по фотографии VIN;
- раздел «🎨 Покраска»: сдача машины по фото автомобиля и VIN, список «На покраске», кнопка «Забрали с покраски», раздел «Покрашены · забрали» и поиск по VIN внутри покраски;
- для покраски нужны только два фото: автомобиль и отдельный VIN-фрагмент;
- подключение к Telegram напрямую: VPN и прокси не требуются; локальный SOCKS5-прокси, если он указан, остаётся только запасным вариантом;
- автоматический выбор способа подключения при запуске и переключение на ходу, если активный способ перестаёт отвечать;
- четыре роли с серверной проверкой прав: главный администратор, администратор, работник и водитель;
- новый пользователь автоматически получает роль водителя и может создавать карточки;
- работник дополнительно ищет по VIN и видит все карточки;
- администратор дополнительно удаляет любые карточки, видит статистику и Telegram ID, переключает роли «работник/водитель» и переименовывает пользователей;
- главный администратор из `ADMIN_USER_IDS` имеет все права, назначает любую из трёх управляемых ролей и переименовывает любого пользователя прямо в Telegram;
- работник и водитель не могут удалять карточки, включая собственные;
- водитель работает с покраской полностью: сдаёт машины, ищет их по VIN, видит «На покраске» и «Покрашены · забрали», сам нажимает «Забрали с покраски»;
- поиск по VIN внутри покраски доступен всем ролям, включая водителя; обычный каталог автомобилей и общий поиск по VIN водителю недоступны;
- обязательная валидация Telegram ID, настроек прокси, текста VIN, поискового запроса, имени пользователя, размеров/типа/уникальности фотографий и данных перед записью в SQLite;
- автоматическая миграция существующей SQLite-базы; прежние администраторы сохраняют роль, остальные существующие пользователи получают роль водителя;
- защита от второго экземпляра процесса;
- два уровня меню: главное меню по разделам и разделы с кнопками;
- единое оформление: заголовок, разделитель, короткие строки и крупные маркеры;
- встроенная инструкция для сотрудников: 9 страниц прямо в боте, есть раздел
  про валидацию фотографий и ввода;
- отдельная инструкция администратора: 7 страниц, видна только в админ-панели
  администратору и главному администратору;
- инструкции листаются кнопками и читаются на телефоне без файлов.

# Deutsch — Cloud-Betrieb ohne PC und ohne Docker

Telegram hostet den Python-Code eines Bots nicht. Für einen vom PC unabhängigen 24/7-Betrieb wird ein Ubuntu-24.04-VPS in der EU benötigt. 2 GB RAM und 15–20 GB SSD werden empfohlen. Domain, Webhook, Docker, VPN und Proxy sind nicht erforderlich.

Projekt nach `/root/VIN-Bot-Cloud` kopieren und installieren:

```bash
cd /root/VIN-Bot-Cloud
bash deploy/install-ubuntu.sh
```

Der Installer richtet Python, Tesseract, den Benutzer `vinbot`, den geheimen `.env`-Token, den automatischen `systemd`-Start sowie tägliche SQLite-Sicherungen ein.

Verwaltung:

```bash
systemctl status vin-telegram-bot
journalctl -u vin-telegram-bot -f
systemctl restart vin-telegram-bot
```

Für die Übernahme vorhandener Karten zuerst den Windows-Bot vollständig stoppen und anschließend dieselbe `data/bot.db` sowie denselben Bot-Token auf dem VPS verwenden. Derselbe Token darf niemals gleichzeitig auf PC und VPS pollen.
